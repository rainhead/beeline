# Determinations and names

Part of Beeline's architecture notes; the index is in [AGENTS.md](../../AGENTS.md#architecture-overview).

Rank is reference data, not free text: `animal_rank` (`schema/020`) holds the ranks the store admits with an `ordinal` gapped by 10, because "species or finer" is the comparison the domain needs and a bare TEXT column cannot answer it — every caller was growing its own copy of the ladder instead (beeline-a2p, beeline-4zi). The numbers live in the table and callers join, which is the half of Symbiota's rank design worth copying without the ~150 bare `rankid > 220` literals that came with it. `TaxonName`'s `ITALIC_RANKS` stays a separate, deliberately wider list — it must do something sensible with a rank the store has never heard of — and a test pins the two to agree wherever they overlap. `determination_misplaced_qualifier` (`schema/115`) is the CHECK the engine cannot hold, since "species or finer" is a fact about `animal_rank` rather than about the determination row: a test asserts it empty, the same shape as `sample_elevation_stale` and for the same reason. A determination says which node and, since beeline-tgu, how sure: `determination.qualifier` holds the three open-nomenclature qualifiers that modify a species assertion (`cf.`, `aff.`, `nr.`) and cannot be expressed by dropping to genus, which would throw away the resemblance the determiner observed; `sp.`/`spp.` are deliberately absent, being what a genus-rank determination already means. `verbatim_identification` keeps the name as the source wrote it beside the node it resolved to, and a CHECK requires it, never blank, on every channel but `legacy_import`: not every name will resolve to a name in the reference the tree is matched against, so the words are the one record of what was said (beeline-45v), while legacy import is exempt because 225,669 of its 256,161 determinations arrive as parted columns with no whole name to keep, and promotion invents none — except where a curated decision sends a determination to a node other than the one its own columns spell (a spelling alias, and next an adopted Ecdysis name), when the spelling the source used is kept here, since nothing else would say what was written (beeline-bph). Only `nr.` is attested in the legacy corpus (3 records, `Lasioglossum nr. tenax`, which used to land on the bare genus because `specificEpithet` is empty on those rows and nothing read the string); the glossary and `/design/names` teach all three. The curated taxonomy is based on the taxonomic thesaurus of Ecdysis, the Symbiota portal the program's taxonomists determine in (beeline-7gob: decided by Peter on 2026-10-23, in a meeting Andony and the program's taxonomists attended); it was ITIS until then (beeline-45v), and ITIS lacked every bee subgenus outside Colletidae, the potter wasps that arrive as bycatch, and names from recent papers that Ecdysis holds because it is where they are used. `animal.ecdysis_tid` is the Ecdysis id of the one name a node matches at its rank and spelling, an accepted name preferred over a synonym — derived by `ingest/match-ecdysis.sql` from `ecdysis_taxon` (`schema/025`), restated whenever the thesaurus is loaded and after legacy promotion, and checked by `animal_ecdysis_stale`. `pnpm ecdysis:taxonomy [db]` fetches it and loads it (`src/fetch-ecdysis-taxonomy.ts`, `src/load-ecdysis-taxonomy.ts`): Symbiota's taxonomy display page exports a branch of the thesaurus as CSV, with no sign-in, and a branch too large for the server to export (Insecta, Coleoptera) answers 500 and is split into its children until each piece answers — 55 exports, 1,028,351 names and about three minutes on 2026-10-23, written as one 72 MB CSV under `data/ecdysis-taxonomy/` — and the load keeps the ranks `animal_rank` admits, Symbiota's rank ids being its ordinals, gives each accepted name its nearest ancestor at one of them (`admitted_parent_tid`, walking past tribes, subfamilies and subgenera, since the tree files a species under its genus, and from a synonym to its accepted name, since 12,915 accepted insect names sit under a synonym and adopting along one would mint a name Ecdysis rejects; a genus Ecdysis spells like a subgenus, `Lasioglossum (Eickwortia)`, ends the walk, so what is filed below it waits for a person), and replaces the table wholesale in one transaction, in about three seconds; `--cached` loads the last fetch without asking Ecdysis again, and `db:reseed` carries the table, since promotion cannot recompute it. Ecdysis has no releases — it is edited name by name — so the day of the fetch is the version. Symbiota gives a synonym exactly one accepted name, so there is no synonym table: `accepted_tid` is a column. Its text is kept as Ecdysis stores it, double-encoded authors in Lepidoptera and Diptera included (no bee name has one), and an export's backslash before a quote is PHP's escape, which a standard CSV reader misreads. All insects rather than only what already matches, because bycatch arrives from any order and adoption and curation look up names the store does not hold yet. `animal_ecdysis` (`schema/118`) says what a node's id, or its absence, means: on the sandbox store of 2026-10-23, 3,492 nodes are accepted, 16 synonyms (kept on their own id, with the name Ecdysis files them under beside it — `Lasioglossum pavonotum` under *pavonotus*, `Peponapis pruinosa` under *Xenoglossa pruinosa*), none homonyms, and 106 absent — mostly checklist names nothing is determined to, plus `Lasioglossum aspilurum`, `Sphecodes (Arctosphecodes)` and `Perdita nuttalliae`, which carry about a hundred determinations between them. `not loaded` is its own answer, so a store without the thesaurus never reads as a taxonomy Ecdysis has never heard of; what the program does about a synonym or an absent name is `animal_curation` (`schema/022`, beeline-45v.1), replayed from `ingest/taxon-curation.csv` by `src/taxon-curation.ts` after the seed and before the match. Ecdysis is the default, so the file holds only the claims — an **addition** (a name Ecdysis lacks, kept), a **departure** (a name Ecdysis calls a synonym, kept under the program's treatment, with what Ecdysis said recorded beside it) and a **homonym** resolution (which of two accepted Ecdysis names at one spelling is meant, by id, which the match then honours) — and every row names the taxonomist who decided and why, with a DOI or link where a paper is behind it, since the loader transcribes a decision and never makes one (Peter, 2026-10-02). It holds no decisions: the workbook sent to Lincoln Best on 2026-10-02, which asked about ITIS's gaps, will not come back (Peter, 2026-10-23), and most of what it asked Ecdysis already answers. A row whose node is not in the tree creates it under the parent its name implies, or under `parent_rank`/`parent_name` for a genus or family; one whose parent is missing is reported, never guessed. `animal_curation_stale` is the check of each later fetch against the decisions — an addition Ecdysis now carries, a departure Ecdysis has adopted (retire it) or filed under yet another name, a homonym choice no longer on offer — empty while the thesaurus is not loaded. When decisions do come, **reading them is a person's or a model's job, never a script's** (Peter, 2026-10-03): an answer comes back as prose, a crossed-out proposal, a row added at the bottom, or an email saying "mostly fine, except…", and the first reader of the workbook — which matched dropdown strings and prefix-matched "Keep…" — would have mapped those with a confidence no reviewer of a forty-row diff catches. So `pnpm taxon:fetch-sheet <sheet-id>` only writes a sheet's tabs to a dated snapshot under `data/taxon-decisions/`, the record of what was said; whoever reads it records each decision with `pnpm taxon:decide <kind> <rank> "<name>" --by "L. Best" --reason "<his words, and where from>" [--reference] [--tid]`, or `--batch file.csv` for forty rows under one signature ("every proposal, as confirmed by email"), and that tool fills in what the reader must not type — Ecdysis's id, the name it files the name under instead, the fetch — refuses a decision the thesaurus contradicts (an addition of a name Ecdysis has, a departure from a name Ecdysis still accepts, a homonym choice not among the candidates), and merges the row into the file. The reason is the taxonomist's words verbatim; a paraphrase is the reader's. `pnpm taxon:apply [db]` replays the file onto an existing store; promotion does the same on every rebuild. On `/taxonomy` a decided name wears a chip in the decision's words ("Kept beyond Ecdysis", "Kept against Ecdysis", "Chosen") in place of the warning, with Ecdysis's view kept beneath; its own page says who decided, when, against which fetch and why, links the reference, and warns when the thesaurus now loaded has moved from under it; the index counts decisions and lists them through a `decided` filter, whose `moved` value is the curation worklist. Names are derived, never typed: `TaxonName` derives italics, subgenus brackets, and qualifier placement from rank, and `labelName()` (`src/person-name.ts`) derives a label's "P. Abrahamsen" from `person.given_name`/`family_name` — family names print whole, `label_name` overrides (`/design/names`). The tree itself is `/taxonomy` (`src/app/taxonomy.ts` + `src/app/views/taxonomy.tsx`, beeline-45v.5), readable by everyone like the glossary and the place curation will land: a name is addressed by rank and name — the table's own unique key, which a rebuild does not redraw, where the name alone is not a key — and its page shows where it is filed, how it stands in `animal_ecdysis` (the accepted name for a synonym, both Ecdysis authors for a homonym, and a link to the name's page on Ecdysis), and what is filed below it, counted by determination of record — and each count links to the specimen listing at `scope=all`, naming it because a link that names no scope lands on whatever scope its reader last browsed, so a count of everyone's could open on their own. A name search or a standing filter turns the index into a flat list, which is the worklist curation grows into; browsing starts where the tree first branches, since Animalia, Arthropoda and Insecta each hold one thing. `/taxonomy.csv` is the whole tree as one file, for a spreadsheet (beeline-7dve): a row per name in the order the pages browse it, Darwin Core's Taxon terms where one fits (`parentNameUsage`, `acceptedNameUsage` for a synonym) with the ancestors at kingdom to genus spelled out on each row, and Beeline's own columns after them — the Ecdysis id and standing, the specimens counted as the pages count them, and any decision. A row speaks about Ecdysis only when the name is not simply accepted there.
