# Determinations from Ecdysis

Part of Beeline's architecture notes; the index is in [AGENTS.md](../../AGENTS.md#architecture-overview).

`pnpm ecdysis:load <archive-dir-or-export.csv> [db] [--prefix WSDA_] [--force]` (`src/load-ecdysis.ts`, beeline-9ut) is the `ecdysis_import` channel: expert determinations made in Ecdysis, Symbiota as WSUC deploys it, brought back as events. Two inputs, one row model — an unpacked Darwin Core archive (`occurrences.*` + `identifications.*`, the whole identification history with, usually, one row flagged current, each with a Symbiota `recordID` and the moment it was entered) or the flat occurrence export staff download today, read as one current identification per occurrence and keyed by the occurrence and its fields. The join is the catalog number under the collection's prefix, and the loader keeps that catalog number, as Ecdysis wrote it, in `specimen_catalog_number`, which is where the exports' `catalogNumber` comes from, since a catalog number is the museum's and is never derived from the field number (gh-98); names resolve against `animal` by spelling; one the tree lacks but Ecdysis's thesaurus accepts is adopted from it first, with whatever ancestors the tree also lacks, walked up `ecdysis_taxon.admitted_parent_tid` (`src/adopt-ecdysis.ts`, beeline-45v.1.1: the thesaurus is the default, so taking its word is no taxonomist's claim — but never a homonym, a subspecies, or a name holding anything but ASCII, which in Ecdysis is double-encoded text rather than a name), and anything else is never minted (curation, beeline-45v.1) — but a bycatch record is not held back for it: it is recorded under the nearest name the tree does hold, the genus its identification names or else, for the current identification only, the family, order or class its occurrence names, with what Ecdysis wrote as `verbatim_identification` and a qualifier moved to the notes, and reported as `filedUnder` (Peter, 2026-10-18: "the bycatch questions absolutely shouldn't block anything", beeline-wqht). Falling back takes evidence that the record is not a bee's, a non-bee family above the node reached or on the occurrence, and none that it is; so a bee's record, one with no family anywhere, a superseded one whose genus the tree lacks (the occurrence classifies only what Ecdysis calls it now), and one whose name two nodes carry still wait and are reported as `unresolvedNames`. A record filed coarser moves to its own name only when the archive is loaded into a store that has it, as after a reseed: a reload skips what its recordID already recorded; determiners go through `ingest/determiner-aliases.csv`. **Ordering is what an import has to get right, and `dateIdentified` cannot help** — "s.d." on two thirds of Ecdysis's identifications, a bare year on the rest, kept as `determined_on` with `determined_on_precision` beside it and shown as the year. The identification Ecdysis calls current — the occurrence's own determination where an archive's history flags none, as 484 of Washington's occurrences do (beeline-9ut.6) — is recorded when it crosses into Beeline, so it supersedes what stood before (the legacy import's undated copy of the same assertion included, which is how a Washington record gains its year); a superseded one is recorded at the moment Ecdysis entered it, so history lands in the past and can never be the record, whichever export brings it. Idempotent twice over: by `recordID` (`ecdysis_identification`), and by adoption — an event on the specimen with the same node, qualifier and determiner that no `recordID` has claimed, recorded from a flat export that could not know the id, is linked to the archive's `recordID` rather than recorded again or skipped; skipping was the first version, and it skipped a superseded row for matching what happened to be current, so the next load recorded it. An older export loaded after a newer one would make since-revised rows current again, so the loader refuses it unless forced; the check is to the minute, since flat exports stamp to the minute and archives to the second. Measured on the dev store in date order — February flat 25,715 loaded, March flat 175, July archive 8,026 of 85,103 with 24,331 already recorded, and the archive again 0 — after which 30,465 of Washington's 30,995 expert records are the dated Ecdysis event. What the exports hold is [docs/research/ecdysis-integration.md](../research/ecdysis-integration.md). The `ecdysis-fetch` job (`src/fetch-ecdysis.ts`, beeline-9ut.1, 3am Pacific, between the sync and the legacy export) keeps Washington's archive current the way beeatlas does: it asks Ecdysis's public v2 API whether dataset 44 has moved since the last download — the total, and the count modified since a day before it — and signs in (`ECDYSIS_USERNAME`/`ECDYSIS_PASSWORD`; the bulk download answers 401 otherwise) to download only if it has, any doubt meaning download. Unchanged upstream still loads, from the archive it kept, because a reseed drops every Ecdysis event and the loader's idempotence makes the reload free; the collections it reads are `ECDYSIS_COLLECTIONS`, Washington's alone until beeline-9ut.2.
