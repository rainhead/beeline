# Programs

Part of Beeline's architecture notes; the index is [README.md](README.md).

`/programs` and `/programs/:code` (`src/app/programs.ts` + `src/app/views/programs.tsx`, beeline-rrit) gather what Beeline knows about each program, which was said in a dozen places: its mark, its leads, how many people belong to it, this season's collectors, samples and specimens, every season's records, whether it prints its own labels, the Ecdysis collection its expert determinations come back from (`ECDYSIS_COLLECTIONS` names the program, as a dataset or a collection), and how to reach it. A program's licence, privacy policy, nightly archives and files for Ecdysis are on its Data tab (below), not on this page. Read by everyone signed in, like the taxonomy, since it shows totals and the program's own leads and nobody's records; the links into the listings and the roster are drawn for staff only. A program is addressed by its code, never by `entity_id`. Its records follow the archives' rule — an atlas's ground, Master Melittology's outside every atlas, and none by geography for the BLM surveys. Contact is the leads, an atlas's website from `ATLAS_IDENTITY` beside its mark, and the email address the program gives for questions, which staff set on the page: each save is a line appended to `data/program-contacts.csv` (`src/program-contacts.ts`, `BEELINE_PROGRAM_CONTACTS`), the latest line for a program standing, so the file is its own history and the nightly backup carries it. Staff never edit a CSV. The address may be a staff member's work address, as the refuge project gives August Jackson's, but never one taken from the legacy register.

A sample's program, on its page and its specimens' pages, is its atlas's, else Master Melittology's (`program_code` in `src/app/record.ts`, beeline-8w8n); its mark sits at the top right of those pages, and Master Melittology has none yet. An atlas's mark (`AtlasMark`) links to its program wherever it is drawn, since an atlas's program code is its atlas code — except on the program's own page, where a link would only reload it, and on the signed-out page, where the program pages are behind sign-in and the mark links to the atlas's own website instead (beeline-8n7r). A program's page shows its photographs, when it has any, as a row the reader scrolls through (`PhotoCarousel`), each credited with its licence. They are files under `src/app/static/programs/<code>/` with an entry each in `src/app/program-photos.ts`, the way the marks are files with an entry in `ATLAS_IDENTITY`: the repository is public, so a photo goes in only with its metadata stripped, since a phone records where every photo was taken, and a test reads each file to hold it to that. The row scrolls with no script; the islands bundle adds Previous and Next.

**A program's code is a key; its abbreviation is what people read** (beeline-uiar). Washington's code is `WaBA`, and the atlas writes WABA (Karla Salp, 2026-11-13). The code could not simply change: it is a unique column on a row that samples, print runs and memberships refer to, and DuckDB refuses to update such a column (duckdb/duckdb#20246), nor will it add a column to that table. So `program_abbreviation` (`schema/010`) is a satellite that nothing refers to, one row per program, its code everywhere but Washington. Pages, print-run titles and scope hints, the roster's Atlas and Leads columns, the unclaimed records, and the `atlas` column of the specimen and sample exports show the abbreviation, each read as `coalesce(abbreviation, code)` so that a program added without a row shows its code rather than vanishing. The code stays wherever it is an address or a key: URLs and the listings' `scope`, the scope cookie, the person overlay's `home_atlas` and `leads` and `/people.csv`, whose `atlas` and `leads` columns mirror them, the program licences file, the Ecdysis collection list, the theme and photos, and the archive file names, which links and the export folder already use.

## The Data tab

`/programs/:code/data` (`src/app/views/program-data.tsx`, beeline-q8di) holds what leaves Beeline for one program, in the order a person acts: its licence and privacy policy as the decisions stand now (`src/program-governance.ts`), for the years the last nightly run wrote archives for (the licence and archive tables list the manifest's years, so a year that first gets specimens today appears after tonight's run; the upload section's years are read live); for a program with an Ecdysis collection, the whole upload to Ecdysis, steps, check and files made ([the-upload-to-ecdysis.md](the-upload-to-ecdysis.md); its numbered steps are the `Steps` component, `src/app/views/components/steps.tsx`, which How Beeline works uses too and `/design/components` shows); then its nightly Darwin Core archives, each year, the checklist and the archive of every year together ([the-legacy-format-export.md](the-legacy-format-export.md)). The page and the tab are two links in a row (`ProgramTabs`, the `Tabs` component), drawn only for a person who may open the tab. `/exports` keeps what spans programs, and lists each program with a link to its tab.

**Who may open it, stated once, here** (Peter, 2026-11-21: the upload to Ecdysis and the program's archives are for the program's leads and admins, not for staff generally, because they hold collectors' names and true coordinates). `programDataAccess` in `src/app/programs.ts` is the rule: a person may open a program's Data tab when they are an admin, or one of the program's leads (`program_lead`, by person id). Everyone else, a lead of a different program included, gets the app's not-found answer, so that the tab's existence is not revealed. Every route under `/programs/:code/data` calls it first (the tab, the nightly archive downloads, the specimens file, the associations file, and the check of Ecdysis), and so does the program page when it decides whether to draw the tab link, so the link and the routes cannot disagree. Each file is also checked to belong to the program in the address: an archive file name must be one the manifest lists for that program, and a recorded download's collection must be that program's, so a lead cannot fetch another program's file by guessing a name or an id. Leading a program grants this access and nothing else, and `program_lead`'s table comment in `schema/010` says so (migration 0117 reissued it). Nothing under the tab is cached: the tab and the nightly archive downloads carry `cache-control: no-store`, as the two Ecdysis files do.

The person asked about is the one signed in, not the person a household delegation acts for: delegation widens whose samples someone reaches, never what they may download. While an admin is impersonating somebody, the tab is drawn as that person would see it (the check uses the impersonated person, and the admin flag is already off), so a lead sees it and a non-lead gets not-found; and every download and action under it is then refused with the read-only message, after the access check. The old addresses `/exports/ecdysis/...` and `/exports/dwca/...` are gone and answer 404 for everyone, admins too. `test/program-data-permission.test.ts` holds the matrix of every route against every kind of person.
