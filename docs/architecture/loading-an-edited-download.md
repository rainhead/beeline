# Loading an edited download

Part of Beeline's architecture notes; the index is [README.md](README.md).

People download the specimens CSV from `/specimens`, edit cells in a spreadsheet, and will upload the edited copy (beeline-kgyd, Peter, 2026-11-16). Mostly they will give determinations; staff will also correct a sample's method, dates and place. Beeline shows every difference and, in a later slice, records the changes.

**What exists so far is the first slice, and it writes nothing to any record.** Staff upload a file at `/uploads` (`src/app/views/uploads.tsx`, the routes in `src/app/server.tsx`) and read a preview at `/uploads/:id` that lists what differs from what Beeline says now and what is held, under a line saying that nothing has been changed and that **applying changes from a file is not built yet**. The routes are admin only and refused while impersonating, as the other staff writes are. The link is on `/specimens` beside the bulk actions and on `/exports`.

**The upload is kept before anything reads it.** `upload` (`schema/047`, an entity, never updated) says who sent the file, when, its name, its SHA-256, its size and how many rows it holds, and an optional `reference`: the request behind the file, an email's message id or an issue link, so that a later change can be traced to who asked for it (never an address or a name). The bytes go to `<uploadsDir>/<upload id>/<name>` (config `uploadsDir`, `BEELINE_UPLOADS`, default `data/uploads`; declared and refused under Vitest like `printRunsDir`), the name reduced to a safe base name by `safeBaseName`. A file that is refused is deleted again and no row is written. The preview reads the kept file and works the plan out again each time, so it always compares with what Beeline says now. The files are on the volume and are not in the nightly backup, which holds the store and the authored CSVs: only the `upload` rows are, so a restored store can name a file it no longer has, and the preview says so.

**The comparison is `src/app/upload-plan.ts`**, a function of the store and the file's bytes that returns a plan (`planUpload`, or `parseUpload` then `comparePlan`). Its decisions:

- **A row is found by `specimenId`**, never by field number, because a field number is not unique, may be absent, and is the cell a spreadsheet damages (a dropped leading zero). A field number column is still read, as a check on the row's identity: a cell that is not the specimen's number holds the row (`number_disagrees`), and a blank cell agrees with a specimen that has none.
- **A change is a cell that differs from what the download would say now**, and "now" is the download itself: `listSpecimens` (a new `ids` option restricts it to the named specimens, read 500 at a time as staff, scope all) through `specimenCsvRow`, so the comparison cannot drift from the file the person edited. The columns are found by name in any order, unknown ones are ignored, and a column the file lacks is never a difference.
- **Both sides are normalised first**, because a spreadsheet rewrites dates, numbers and encodings without anyone editing the cell: text is trimmed and the quote the download puts before a cell that would read as a formula is taken off (the inverse of `csvCell`); sex, qualifier and caste ignore case; coordinates and uncertainty compare as numbers; dates are read as ISO or `M/D/YYYY`. A cell that is not a number or not a date is held for that cell alone (`number_unreadable`, `date_unreadable`) rather than called a difference.
- **Each differing cell gets a kind by its column**: `determination` (scientific name, qualifier, sex, caste, determiner, date identified), `method_dates`, `place`, `coordinates`, `disposition` (disposition and remarks), and `not_applied` for everything else.
- **`identifiedByExpert` is never read from a file.** The determination of record ranks expert determinations first (`schema/110`), so a flipped cell would outrank every other determination for good. It, the authorship, the rank and the host columns are listed apart, in a collapsed section, as differences that Beeline does not take from a file.
- **A file edited against something Beeline no longer says is held, not applied.** A determination difference is held (`determination_changed_since`) when the row's `determinationId` is not the determination of record now, and a sample-level difference (`sample_changed_since`) when its `sampleVersion` is not the sample's now. A file lacking the column cannot say what it was edited against, so those are held as `column_missing`.
- **A sample's change is one change, not one per row.** The file repeats a sample's cells on every specimen row. If the rows of one sample do not all say the same thing in a column where one differs from Beeline, nothing can tell which is meant, and the column is held (`rows_disagree`); otherwise it is one change for the sample, carrying how many of the sample's specimens the file holds and has in all, and whether its labels are on paper (`printed_sample`), which is what a later slice needs to decide whether a change reaches a printed label.
- **A row is held and the rest of the file goes on; a whole file is refused only when it cannot be read**: over 20 MB, not UTF-8, no `specimenId` column, no data rows, or more than 20,000 of them. A held row contributes no differences. Counts are split by active and settled season with `settled_sample` ([CONTEXT.md](../../CONTEXT.md), Season); a row naming no specimen has no season and is counted apart.

The parser is small and lives in the module (`parseCsvRecords`): RFC 4180, a BOM stripped, `\n`, `\r\n` or a lone `\r`, blank lines skipped. The tests (`test/upload-plan.test.ts`, `test/uploads-app.test.ts`) build their input from the app's own `/specimens.csv?scope=all`, so an unedited file compares as no differences at all, including after a round trip that adds a BOM and carriage returns.

Not built yet: applying anything, recording who changed what and on whose request, and the determination and sample paths a plan would feed. The preview's `kind` and `held` names are what those slices will read.
