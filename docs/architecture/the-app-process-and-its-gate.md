# The app process, and its gate

Part of Beeline's architecture notes; the index is in [AGENTS.md](../../AGENTS.md#architecture-overview).

The web app (`src/app/`) is the process that owns the database — [ADR 0005](../adr/0005-app-process-owns-the-store.md): Hono with `hono/jsx` SSR views, Lit light-DOM islands built by Vite, MD3 color tokens generated from a seed (`src/app/theme/tokens.ts`), every route session-gated by construction — and the gate remembers the URL it refused, so signing in lands you on the page you asked for rather than home (same-site GET paths only, carried in a short-lived cookie beside the OAuth state, beeline-2c3.31); `/design` is the design system (component library in `src/app/views/components/`, stylesheets split `elements`/`layout`/`components` under `src/app/static/`, every section rendering live from the real tokens), offered only to admins but not gated — it reads no records, so walling a curious volunteer out of it protects nothing; the reason it is not offered to them is that it is not their tool — and `/glossary` is its volunteer-facing counterpart. The header nav carries only the records people work through, `/samples` and `/specimens`; everything else a person can open — the glossary, the taxonomy, the staff tools — lives in the menu left of the brand, grouped by what it is for rather than by who may use it, and each item is shown only to whoever may open it (beeline-45v.5); on a phone the records collapse into it too. Beside it, in the header itself and never in a menu, is "Send feedback": a mailto to `BEELINE_FEEDBACK_EMAIL` (no address, no link) pre-filled with the page, the time, the browser and the session — the session as the first 12 hex digits of its id's SHA-256, since the id is the bearer credential and an email carrying it would let whoever read it sign in; `sha256(id)` in the private store finds the row. The account menu is for the person signed in and their own things — signing out, acting for someone, and later their mailing address — and never a place to find pages. Every response carries a Content-Security-Policy and its companion headers from one middleware registered first (`src/app/security-headers.ts`, beeline-m9o): same-origin scripts, styles, fetches and forms, iNaturalist's static host for the avatar, no framing, and inline `style=` attributes allowed while inline `<style>` and script are not; the Referrer-Policy keeps a same-origin referrer because the error page's way back reads it. Auth is iNat OAuth; sessions and sign-in records (`inat_sign_in`, which held volunteers' OAuth tokens until those were dropped and is kept with no purge, beeline-cj6/zg4) live in the attached private store ([ADR 0003](../adr/0003-private-data-store.md)), whose schema is `schema/private/*.sql`, applied by the app at boot when missing — a renamed table is renamed in place before that, and every `COMMENT ON` that differs from the DDL is rewritten, since applying a file only to a missing table never carried a corrected comment to a deployed store.
